Kaleido without a browser: kaleido-lite

plotly.js runs in a light fake DOM (linkedom) inside a QuickJS standalone binary. A shim answers the few layout questions plotly asks (text size, computed style, path length, canvas pixels), plotly writes its own SVG, and resvg rasterizes it. WebGL goes through ANGLE on SwiftShader, and MathJax runs in a spike build. Every pair below shows headless Chrome on the left and the binary on the right, with the same plotly.js 4.1.1 and the same fonts, rendered on a GitHub macOS runner for this page.

  • Renders: scatter, bar, box, violin, contour, heatmap, image, pie, sunburst, treemap, funnel, waterfall, candlestick, polar, ternary, sankey, table, indicator, geo, and the WebGL traces: scattergl, splom, parcoords and all 3D traces.
  • Does not render: map subplots (MapLibre needs WebGL 2) and, in the MathJax spike, tables with TeX.
  • Pixel differences count pixels whose RGB distance from Chrome exceeds 60. Below about 2% it is text antialiasing (resvg against Skia).
  • Two Chrome references. 2D figures are compared with a screenshot of the plot on screen, and the binary applies the two rules of plotly's page stylesheet that change pixels. WebGL and MathJax figures are compared with Plotly.toImage in Chrome (the screenshot misses 3D scenes), which, like Kaleido, rasterizes the bare SVG; the binary then skips those rules too (PAGE_CSS=0).
  • Times are wall-clock seconds for one process per figure, start to PNG, on this runner.

CSS-only styling

resvg ignores some of the CSS plotly relies on, so the shim writes it into plain SVG before rasterizing: text-transform and small caps go into the text and its measurement, text-decoration-line becomes SVG text-decoration, text-shadow becomes a filter, and two page-stylesheet rules apply (crisp axis lines, link colour). These were the outliers before that pass.

{{CSS}}

WebGL and 3D

The binary has a built-in qjs:webgl module: headless-gl's native layer ported to QuickJS, with headless-gl's own JavaScript layer on top, on ANGLE loaded from next to the binary. It runs on SwiftShader by default, so it needs no GPU and draws the same pixels on every OS. plotly reads the canvases back into the SVG as images, as in a browser. Sorted by difference; the time chip shows how slow some 3D figures still are in QuickJS.

MathJax (spike)

A second binary loads MathJax 3 on the fake DOM before plotly, and the shim measures MathJax's SVG output (sizes in ex, nested viewports). The references load the same MathJax in Chrome.

{{MJ}}

Other plotly.js releases

The binary embeds plotly.js 4.1.1. --plotly <file | version> loads any other release at run time: a file, or a version number fetched from cdn.plot.ly once. The first run compiles it (about 0.5 s) and caches the bytecode, so later runs load it in about 45 ms. The one source patch (3D text from glyph outlines) finds its place by the shape of the code, so it applies to every release below. Each row renders the same mock samples, scored against Chrome running that same release; times are medians.

Linux without X

Chrome's own Linux ANGLE links against X11, which minimal servers and containers lack. The angle-linux workflow builds ANGLE with SwiftShader from the commit Chromium 148 ships, with X11 and Wayland off: about 3.5 minutes of checkout and 8 minutes of build on a 4-core runner. Its libraries need only libc, libm, libdl, libpthread and libgcc_s, and the native self-test passes in a Debian container without X libraries, where Chrome's files fail to load.

What is left

  • Fonts: the shim and resvg read macOS system fonts, so figures only render on macOS so far. A release would ship its fonts or find them per OS.
  • Release binaries per OS from CI: Linux ANGLE already builds there, macOS and Windows can use Chrome for Testing's ANGLE.
  • Speed of plotly's heavy 3D maths in QuickJS: isosurface and volume traces take 7 to 17 s (plain JS loops that only a JIT engine runs fast). 3D text, the old worst case, is now triangulated from glyph outlines.
  • MathJax: measure ex as Chrome does, support tables with TeX, and decide whether every build loads it.
  • Kaleido's stdin JSON protocol, so PlotlyKaleido.jl can use the binary.
